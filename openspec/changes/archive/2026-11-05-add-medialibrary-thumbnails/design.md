## Context

Зображення зараз — рядки-шляхи в колонках `games.cover_image` (NOT NULL), `news_articles.cover_image`, `creators.avatar`, `companies.logo_path`. Шлях може бути: статичний файл у `public/assets/...` (сід-дані, ~120 МБ), файл на диску `public` (`storage/...`) або завантаження компаній у `public/uploads/companies`. Єдина точка формування URL — `App\Support\PublicImage::url`. Картки читають `cover_url`/`avatar_url`/`logo_url`. Пошукова індексація кладе в документ сирий шлях (`DocumentMapper`). Сідери/фабрики пишуть шляхи прямо в колонки (обходять observer-и). Черга — `database`, воркера локально немає. php-fpm `memory_limit` = 512 МБ, GD з підтримкою WebP. Попередня самописна генерація — див. proposal.md.

## Goals / Non-Goals

**Goals:**
- Стандартне рішення (Spatie Media Library) замість власного коду обробки зображень.
- Thumb/large для всіх видів зображень, що показуються в картках і банерах.
- Безпечний перехід: наявні дані й сідери/фабрики працюють без змін; жодних втрат оригіналів.

**Non-Goals:**
- Міграція `screenshots` ігор та галереї (лишаються шляхами).
- Responsive images (`srcset`), CDN, S3, ліниве/асинхронне опрацювання черги.
- Видалення старих колонок-шляхів (лишаються як запасний варіант і для фабрик/сідерів).
- Зміна обмежень завантаження (4 МБ/2 МБ) чи форматів.

## Decisions

1. **`spatie/laravel-medialibrary` ^11, диск `public`.** Conversions у `registerMediaConversions` кожної моделі: `Fit::Max` по ширині (без збільшення), `format('webp')`, якість 80. Альтернатива — `spatie/image` напряму: давала б лише обробку, але не зберігання/видалення/життєвий цикл файлів, тож довелось би знову писати власний шар.

2. **Колекції:** `cover` (Game, Article), `avatar` (Creator), `logo` (Company) — усі `singleFile()`. Conversions: `thumb` 640 (обкладинки) / 480 (аватари, логотипи), `large` 1280 (лише обкладинки). Розміри з розрахунку 2× від максимального відображення (постер 300×450, hero ≈ 1280).

3. **Синхронні conversions** (`queue_conversions_by_default = false` у конфігу): воркера локально немає, а чекати чергу, щоб побачити нове зображення в адмінці, незручно. Обмеження завантаження (4 МБ) тримає запит у розумних межах. На проді можна ввімкнути чергу змінною.

4. **Спільний трейт `App\Models\Concerns\HasImageMedia`** з трьома точками налаштування на модель (назва колекції, колонка-шлях, плейсхолдер, розмір thumb) і методами: `imageUrl(?string $conversion)`, `hasImage()`, `imageSearchPath()`. Модель визначає лише тонкі акцесори `cover_url`/`cover_thumb_url`/`cover_large_url` тощо (імена атрибутів, що вже використовуються у Blade, зберігаються — шаблони міняються мінімально). Логіка запасного варіанта: media (+conversion, якщо згенеровано) → старий шлях через `PublicImage::url` → плейсхолдер.

5. **Колонки-шляхи лишаються** (запасний варіант + фабрики/сідери/тести без змін). `games.cover_image` стає nullable (нові записи її не заповнюють). Нове завантаження в адмінці пише лише в Media Library й обнуляє колонку, видаляючи старий файл із диска `public`, якщо він там був.

6. **Імпорт:** команда `media:import-legacy` (по моделях, `chunk`), `addMedia($абсолютний шлях)->preservingOriginal()->toMediaCollection(...)`; пропускає записи з наявним медіа, зовнішні URL і відсутні файли. Виконується після сідерів і одноразово на проді. Конвертація великих JPEG потребує пам'яті — команду запускати з `php -d memory_limit=2G`. Альтернатива «імпорт у міграції» відкинута: довга й важка операція, а міграції мають бути швидкими й відкатними.

7. **`protected $with = ['media']`** на чотирьох моделях: Media Library читає завантажене відношення `media`, тож картки не роблять запит на кожен елемент. Додатковий запит один на колекцію моделей.

8. **Пошук:** `DocumentMapper` бере `imageSearchPath()` — відносний шлях до thumb (`parse_url(..., PHP_URL_PATH)`), інакше старий шлях; `PublicImage::url` уже вміє відносні шляхи, тож клієнтський код не змінюється. Потрібен `search:reindex` після імпорту.

9. **Прибирається власний код:** `ImageVariants`, `PublicImage::variant`, `images:optimize`, тест, `.gitignore`-запис, `cover_thumb_url`-логіка на `PublicImage`.

10. **Розміри — глобальні налаштування в БД** (таблиця `settings`, ключ→значення JSON, модель `Setting`, обгортка `AppSupportImageSizes` з дефолтами): `registerMediaConversions` читає ширини з неї. Ключі: `cover.thumb.desktop|mobile`, `cover.large.desktop|mobile`, `avatar.thumb`, `logo.thumb`; дефолти 640/360, 1280/720, 480, 480. Альтернативи (окремі розміри в кожній формі, окремі файли для мобілки) відкинуті: розміри — властивість дизайну сайту, а не запису.

11. **Conversions обкладинок:** `thumb`, `thumb_mobile`, `large`, `large_mobile` (WebP, `Fit::Max`). Мобільний віддається вікнам до 720 px через `<img srcset="mobile Nw, desktop Mw" sizes="(max-width: 720px) 1px, 100000px">`: у вузьких вікнах слот «1px» змушує браузер узяти найменшого кандидата (мобільний) незалежно від DPR, у широких — найбільшого (десктопний). Обгортка `<picture>` (спершу з `display: contents`) відкинута: у Chromium вона ламала розкладку hero гри (грід-елемент `img` у `picture` ставав у другу колонку); `srcset`/`sizes` не додає елементів. Брейкпоїнт 720 px збігається з `$bp-sm`. Рендерить Blade-компонент `<x-cover>`.

12. **Перегенерація:** після зміни розмірів ставиться в чергу job, що викликає `media-library:regenerate --force`; потрібен queue worker (на проді він і так потрібен для пошуку). Локально без воркера — `php artisan queue:work --stop-when-empty`.

## Risks / Trade-offs

- [Дублювання оригіналів: після імпорту оригінал є і в `public/assets/images`, і в `storage/app/public/{id}`] → стара копія — це запасний варіант і git-tracked сід; зайвий обсяг на диску прийнятний, оригінали більше не віддаються.
- [Конвертація 15-МБ JPEG при імпорті може вичерпати пам'ять] → `memory_limit=2G` для команди, помилка на одному файлі не зупиняє імпорт (лог і далі).
- [Синхронні conversions сповільнюють завантаження в адмінці] → обмеження 4 МБ; при потребі увімкнути чергу.
- [`$with = ['media']` додає запит навіть там, де зображення не потрібні (API, адмінські списки без картинок)] → один запит на колекцію, дешево; прибрати через `withoutGlobalScopes`/`without('media')` за потреби.
- [Доки не виконано `storage:link`, URL у `storage/` не віддаються] → вже вимога для завантажень з адмінки; зафіксувати в деплої.
- [Тести, що створюють моделі з фабрик, не мають медіа] → працює запасний варіант; нові тести явно додають медіа через `Storage::fake('public')`.

## Migration Plan

1. `composer install`, `php artisan migrate` (таблиця `media`, nullable `games.cover_image`), `storage:link`.
2. `php -d memory_limit=2G artisan media:import-legacy`, потім `php artisan search:reindex`.
3. Відкат: вернути гілку; колонки-шляхи не чіпались, тож сайт одразу показує оригінали; таблицю `media` можна лишити.
