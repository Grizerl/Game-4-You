## Context

Поточний стан (див. proposal.md): 8 CSS у `public/assets/css`, віддаються як статика через `<link href="/assets/css/...">` (`layouts/main`, `pages/*/partials/assets.blade.php`); `resources/css/app.css` (Tailwind) через `@vite` у `layouts/app|guest`; 12 inline-`<style>` в адмінці (layout + 11 шаблонів, у тому числі `_form`-партіали, що інклюдяться в create/edit). `public/build` у `.gitignore`. Vite 6 уже встановлений, `sass` — ні. Усі команди node/composer — через контейнер `workspace-84`.

Спостереження, що впливають на підхід:
- Публічний CSS використовує **CSS custom properties** (`--gm-*`, `--clr-*`, `--cr-*`) зі scope на кореневих класах сторінок; це runtime-тема, а не SCSS-змінні.
- У трьох сторінках списків адмінки (`game|creators|company/index`) блок стилів побайтово однаковий; форми компаній/творців відрізняються лише `.logo-preview`/`.avatar-preview`.
- `url(../images/...)` у `creators.css`/`companies.css` — відносні; Vite перепише їх відносно SCSS-файлу, тому потрібні абсолютні `/assets/images/...`.
- `index.css` починався з `@charset` і `@import url(fonts.googleapis...)` (пізніше шрифти винесено в `<link>` у layout, див. рішення 6).

## Goals / Non-Goals

**Goals:**
- Один Sass-конвеєр у Vite для всіх стилів; вигляд не змінюється.
- Доказова еквівалентність: автоматичне порівняння скомпільованого CSS зі знімком оригіналу.
- Усунути дублювання в адмінці через партіали.

**Non-Goals:**
- Редизайн, перейменування класів, зміна розмітки, зміна брейкпоїнтів чи кольорів.
- Заміна CSS custom properties на SCSS-змінні (вони потрібні в runtime для тем сторінок).
- Перехід Tailwind → власні утиліти або видалення Tailwind.
- Мінімізація/оптимізація CSS понад те, що робить Vite у production-збірці.
- Інлайн-значення, залежні від даних (`--i`, `--d`, `--hue`, `width: N%`) і Alpine-стани `display`.

## Decisions

1. **Vite + `sass` (JS-реалізація), без окремого Sass CLI.** Laravel-Vite-plugin уже в проєкті; `sass` не потребує нативних бінарників і однаково працює в контейнері й на Windows. Альтернатива `sass-embedded` швидша, але тягне платформні бінарники — зайвий ризик для CI/деплою.

2. **Структура `resources/scss/`:**
   - `abstracts/` — `_variables.scss` (SCSS-змінні: брейкпоїнти, повторювані кольори адмінки), `_mixins.scss` (`respond-max($px)`, `reduced-motion`);
   - `public/` — входи `index|details|search|games|creators|companies|home|news.scss`, усередині — секційні партіали (`_navbar`, `_footer`, …) там, де файл великий;
   - `admin/` — `admin.scss` (каркас/layout), партіали `_list`, `_form`, `_pager`, `_status`, сторінкові входи (`game-form`, `news-form`, `category-*`, …);
   - `app.scss` — Tailwind.
   Альтернатива «один бандл на весь сайт» відкинута: змінить каскад і розмір стилів на сторінках, де їх раніше не було (різні сторінки навмисно мають різні префікси й глобальні селектори на кшталт `label`, `input` в адмінці).

3. **Порядок і каскад зберігаються** — кожна Blade-сторінка підключає ті самі входи в тому самому порядку (`@vite(['resources/scss/public/index.scss', ...])`; для `@stack('styles')` на головній порядок games → news → home). Адмінка: layout-вхід у `<head>`, сторінковий — через `@push('styles')` у `<head>` після нього, тож правила, що раніше стояли в `<body>` після layout-стилів, перемагають за тими самими правилами специфічності.

4. **Нормалізація без зміни семантики.** Вкладеність використовується лише для **сусідніх** правил (`.a`, потім `.a:hover`, `.a .b`), щоб порядок у виході не змінювався; `@media` лишаються на верхньому рівні (вкладені — лише всередині блоку media). Правила зі списками селекторів не вкладаються. Брейкпоїнти — через міксин з тим самим `max-width`. Конвертація виконується скриптом із наступною перевіркою паритету (див. 5), решта (змінні, міксини, партіали адмінки) — вручну.

5. **Перевірка паритету скриптом** (`postcss` уже є): знімок оригінальних CSS (з git) і скомпільований вихід Sass розбираються в плоский список `(@-контекст, селектор, декларації)`, нормалізуються (пробіли, регістр hex, `0.5`/`.5`, лапки) і порівнюються по порядку. Для адмінки очікуване значення = layout-блок + блок(и) сторінки в порядку документа. Скрипт — одноразовий, у репозиторій не додається, результат фіксується в tasks.

6. **`url()` → абсолютні `/assets/images/...`** (Vite не чіпає абсолютні шляхи, а файли лишаються в `public/`). Google Fonts винесено з `@import` у CSS у `<link rel="preconnect">` + `<link rel="stylesheet">` у `layouts/main` — так шрифти вантажаться паралельно зі стилями, а не після них.

7. **Статичні inline-стилі → класи** (`.inline-form`, `.sep`-стилі в адмінці, відступ футера); динамічні лишаються. Модалка/дропдаун Breeze (`display` керується Alpine/`$show`) не чіпаємо.

8. **Тести:** `Tests\TestCase::setUp` підміняє `Illuminate\Foundation\Vite` заглушкою, що виводить `<link>`/`<script>` з іменами входів; `public/build` не коммітиться, а справжній `@vite` без manifest кидає виняток. Заглушка (а не `withoutVite()`) потрібна, щоб тести могли перевіряти, які стилі підключила сторінка.

## Risks / Trade-offs

- [Зміна вигляду через зсув каскаду] → побітова перевірка паритету правил + збереження порядку входів; візуальна перевірка ключових сторінок у браузері.
- [Прод без `npm run build` покаже сторінки без стилів] → зафіксувати в `CLAUDE.md`/proposal як обовʼязковий крок деплою; `@vite` кидає явну помилку, а не мовчить.
- [Vite хешує імена файлів → кеш браузера інвалідується один раз] → очікувано й безпечно.
- [Vite/postcss може додати вендорні префікси (`autoprefixer`) до публічних стилів] → префікси лише додають сумісність; у перевірці паритету порівнюємо до PostCSS (чистий вихід Sass), а `-webkit-*`-декларації вже є в оригіналі.
- [Глобальні селектори адмінки (`label`, `input`) переїдуть у зовнішній файл] → вони підключаються лише на тих сторінках, де були inline, тож область дії та сама.
- [Старі зовнішні посилання на `/assets/css/*.css`] → усередині проєкту їх немає (перевірено grep); зовнішніх споживачів не очікується.

## Migration Plan

1. Встановити `sass`, налаштувати Vite, зняти знімок оригінальних CSS у каталог перевірки.
2. Конвертувати публічні файли → перевірити паритет → перемкнути Blade на `@vite` → видалити старі CSS.
3. Конвертувати Tailwind `app.css` → `app.scss`.
4. Винести адмін-стилі, перемкнути шаблони, перевірити паритет.
5. Замінити статичні inline-стилі класами; оновити тести й документацію.
6. `npm run build` + перевірка сторінок у браузері й `php artisan test`.
Відкат: `git revert` гілки; `public/assets/css/*.css` лишаються в історії.
